# Engineering Plan

> Status: draft v6 — 2026-11-02 (fifth review: CLI source and flags, full client export list, Node API return type).
> Scope: the engineering path from the inherited `openapi-typescript` codebase to `openapi-typesafe` 1.0.
> This document is the single source of truth for *how* we build. Product goals live in the README.

---

## 1. Mission

Ship a **drop-in, TypeScript 7–ready successor** to `openapi-typescript` and `openapi-fetch`:

1. **Drop-in.** Existing projects migrate by changing package names. Generated output and client API stay compatible.
   Intentional output differences are limited to: the product name in generated text (the file header and the JSDoc
   added to discriminator properties, task 1.1),
   unreleased upstream fixes already on the fork base (§2), and bug fixes we ship (task 7.4). Each one is listed
   in the compatibility report. One intentional Node API difference: `openapiTS()` returns IR nodes instead of
   `ts.Node[]` (task 6.1); code that only passes the result to `astToString()` keeps working.
2. **TypeScript-version independent.** The generator does not depend on the TypeScript compiler API at runtime.
   The only exception is an opt-in compatibility bridge for legacy AST callbacks (task 6.4), loaded on demand through
   an optional peer dependency. Output type-checks on TS 5.x (lowest supported 5.x fixed in ADR-006), 6.x and 7.x.
3. **Verifiably compatible.** Every release ships a public compatibility report against a large corpus of real-world schemas.
4. **Secure by construction.** Minimal dependencies, provenance-signed releases, no long-lived publish tokens.
5. **Clean code.** SOLID, DRY (rule of three), KISS, YAGNI. Every module is small, pure where possible, injectable, and tested.

### Non-goals (for 1.0)

- New features beyond the inherited feature set and the top of the inherited backlog.
- A runtime validator, a server framework, or a mock server.
- Swagger 2.0 input (the original dropped it in v6.0; the generator rejects `swagger: "2.0"` documents; we keep that decision).

## 4. Architecture

### 4.1. Layers (generator)

Dependencies point inward only. Enforced by `dependency-cruiser` in CI.

```
cli/  ─┐
api/  ─┼──►  application/  ──►  domain/
       │          ▲
adapters/ ────────┘
```

| Layer | Contents | May import |
|---|---|---|
| `domain/` | OpenAPI document types; **Type IR** (§4.2); naming rules; pure invariants | nothing outside `domain/` |
| `application/` | Transformers (OpenAPI → IR), the IR printer (IR → text), the `generate` use case, ports (interfaces) | `domain/` |
| `adapters/` | Schema loading and `$ref` bundling, YAML/JSON parsing, file system, terminal logger, optional TypeScript-AST compat bridge | `application/` ports, `domain/` |
| `cli/` | Argument parsing, exit codes, composition root for CLI | everything (it wires the graph) |
| `api/` | Public Node API: `openapiTS`, `astToString`, helper re-exports; composition root for programmatic use | everything |

### 4.2. Type IR (the core design decision)

A small, closed, immutable set of nodes that describes TypeScript **types and declarations** we emit. It replaces `ts.Node`.

- Type nodes: `keyword` (string, number, boolean, null, undefined, unknown, never), `literal`, `reference`, `array`, `tuple`, `union`, `intersection`, `object` (properties, index signatures), `indexedAccess`, `typeOperator` (`readonly`), `utility` (`Omit`, `Record`, `WithRequired`), `raw` (escape hatch for user callbacks, task 6.3).
- Declarations: `interface`, `typeAlias`, `enum`, `constArray`, `export`.
- Footer: helper declarations that must appear once per file (e.g. `type WithRequired<T, K extends keyof T> = …`),
  collected per run in `TransformContext` instead of being parsed from strings.
- Trivia: JSDoc comments attached to nodes.
- Nodes are plain readonly data with a `kind` discriminator. No classes, no methods.
- Constructors **do not normalize implicitly** (no automatic flattening, de-duplication or sorting). The original
  de-duplicates and sorts only in specific places (`tsDedupe`, `--alphabetize`); the IR offers these as explicit
  functions that transformers call in exactly those places. Implicit normalization would silently change output.
- The node set is **closed** and owned by the domain → exhaustive `switch` with a `never` check is the correct dispatch (CODING_PRINCIPLES §3.2, closed sum types). New node kinds break the build in every place that must handle them.

### 4.3. Printer

- Pure function `printNodes(nodes, printOptions) → string`.
- Deterministic: same input → byte-identical output. No dependence on object key order beyond what the IR specifies.
- Responsible for identifier quoting, string escaping, JSDoc rendering, indentation, and line breaks matching the original output format.
- Formatting rules are data (a `PrintOptions` value), not branches scattered across the code.

### 4.4. Transformers

- One module per OpenAPI object (`schema`, `parameter`, `parametersArray`, `operation`, `pathItem`, `paths`, `pathsEnum`, `components`, `responses`, `response`, `requestBody`, `header`, `mediaType`, `webhooks`), matching the current structure to keep diffs reviewable.
- Each transformer is a pure function: `(openApiObject, TransformContext) → IR`.
- `TransformContext` carries per-run state explicitly (resolved refs, enum registry, options, logger). No module-level state.
- `schema` is decomposed into focused functions per schema shape (`enum`, `const`, `oneOf`, `anyOf`, `allOf`, `discriminator`, `object`, `array`, `primitive`, `nullable`), each ≤ 30 lines.
- Shape dispatch uses an ordered, internal list of `SchemaRule` objects (`matches(schema) / transform(schema, context)`).
  The order encodes the original precedence (`$ref` before `enum` before `oneOf`, …) explicitly and makes each rule
  testable in isolation. It replaces a long `if/else` chain; it is **not** a public plugin point (§5.10, YAGNI).

### 4.5. Ports (interfaces) and dependency injection

| Port | Responsibility | Default adapter | Test adapter |
|---|---|---|---|
| `SchemaLoader` | Read a document from every inherited source type (path or YAML/JSON string, `URL`, parsed object, `Buffer`, `Readable`); bundle `$ref` | Redocly-based loader (ADR-005 decides) | In-memory loader |
| `FileWriter` | Write generated output | Node `fs` writer | In-memory writer |
| `Logger` | Warnings and errors | Terminal logger (colors when supported) | Recording logger |
| `TypeAstBridge` (optional) | Convert legacy `ts.TypeNode` callbacks ↔ IR | Lazy-loaded TS bridge in `adapters/type-ast-bridge/` (dynamic import of `typescript` ≤ 6, falling back to the side-by-side package `@typescript/typescript6` that TS 7 projects can install; both are optional peers) | Own test suite with TS 6 |

- Wiring happens only in composition roots (`cli/`, `api/`). Application code receives ports through function parameters or factory arguments — never imports adapters.
- Tests replace adapters with in-memory fakes, not mocks.

### 4.6. Errors

- Domain and application errors are typed classes with a stable `code` (e.g. `SCHEMA_REF_NOT_FOUND`, `SCHEMA_INVALID`, `OUTPUT_WRITE_FAILED`) and structured `details`.
- The CLI maps codes to messages and exit codes. No error is swallowed; no empty `catch`.

### 4.7. Client (`openapi-typesafe-fetch`)

- Keep the public API compatible: **every export of the current `index.d.ts`** — `createClient` (default export),
  `createPathBasedClient`, `wrapAsPathBasedClient`, the serializers (`createQuerySerializer`, `serializePrimitiveParam`,
  `serializeObjectParam`, `serializeArrayParam`, `defaultPathSerializer`, `defaultBodySerializer`), `createFinalURL`,
  `mergeHeaders`, `removeTrailingSlash`, all exported types — plus client behavior: HTTP method functions, middleware
  (`use` / `eject`), the `querySerializer` / `bodySerializer` / `pathSerializer` / `parseAs` options.
  An export-list snapshot test fails if any export disappears.
- Only runtime dependency: `openapi-typesafe-helpers` → evaluate inlining it to reach zero.
- Bundle size budget enforced by `size-limit`. Inherited budget: 7.5 kB for `dist/index.mjs`, measured **bundled and
  minified by size-limit, uncompressed** (`brotli: false`). Baseline: 7.2 kB with size-limit 12 (esbuild) and 7.41 kB
  with size-limit 14 (rolldown) for the same code (`research/baseline.md`). Only 90 bytes of headroom: keep or lower.
  The inherited `pnpm size` script never ran the check (baseline defect B4); CI runs `size-limit` directly.
- Source language: today JS + hand-written `.d.ts`. ADR-008 decides whether to convert to TypeScript; a conversion must
  keep the emitted bundle within budget and the public `.d.ts` identical (checked with `attw` and a type-identity test).

## 5. Engineering principles (binding)

All code follows `CODING_PRINCIPLES.md`. Project-specific rules:

1. **Language.** All code, comments, docs, commit messages, issues and PRs are in English.
2. **TypeScript.** `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitOverride`, `verbatimModuleSyntax`. No `any` without an explaining comment and an issue link.
3. **Sizes.** Function ≤ 30 lines, ≤ 4 parameters (use an options object), nesting ≤ 3, line ≤ 100 chars.
   Files: target ≤ 300 lines (hard limit from principles: 3,000). Enforced by a lint rule where the linter supports it,
   otherwise by a small check script in CI.
4. **Exports.** Named exports internally. Default exports only where the inherited public API requires them
   (`openapiTS` in the generator, `createClient` in the fetch client and in the React Query bindings).
5. **Purity.** Domain and application code are pure: no I/O, no `Date.now()`, no `Math.random()`, no environment access.
6. **No hidden state.** No module-level mutable values. Per-run state lives in `TransformContext`.
7. **Naming.** Expressive, no abbreviations except the standard ones (API, URL, JSON, IR, AST). No `Util`, `Helper`, `Manager` modules — name the concept (`identifiers.ts`, `jsdoc.ts`, `string-escape.ts`).
8. **Comments explain why.** Docstrings on every exported function: purpose, edge cases, invariants.
9. **DRY with judgment.** Extract on the third repetition, and only when the pieces express the same concept.
10. **KISS / YAGNI.** No plugin system, no configuration we do not need today. The IR has exactly the node kinds the output needs.
11. **Zero warnings.** Biome, `tsc`, tests, and install logs must be clean.
12. **Every behavior change has a test**; every bug fix starts with a failing test.

### Phase 5 — Transformer migration (week 3–5, strangler pattern)

Migrate one transformer at a time, **leaves first**. After every step: no regressions — every spec that matched before
the step still matches (subset on every commit, full corpus at the end of each step).

| Order | Module | Notes |
|---|---|---|
| 1 | Primitives, literals, `$ref` (`oapiRef`) | Smallest surface |
| 2 | `schema-object` — split into `SchemaRule`s (§4.4) | Largest file; split before porting |
| 3 | `media-type`, `header`, `parameter`, `parameters-array` | |
| 4 | `request-body`, `response`, `responses` | |
| 5 | `operation`, `path-item`, `paths`, `paths-enum`, `webhooks` | |
| 6 | `components`, root transform, enum registry (replaces `enumCache`) | Removes module-level state |
| 7 | Switch output printing from the TypeScript printer to our printer (§4.3) | Corpus: no regressions |

Rules during migration:
- Leaves are ported first, so ported children produce IR while their unported parents still build `ts.Node`.
  A **temporary IR → `ts.Node` converter** feeds IR into unported parents. Until step 7 the output is still printed
  by the TypeScript printer, so the harness measures transformer correctness separately from printer correctness.
- The public Node API keeps returning `ts.Node[]` during this phase (through the same converter), so the inherited
  Node API tests stay green. TypeScript is removed only in Phase 6, after the public API switches to IR.
- No behavior changes in this phase. Bug fixes from the backlog wait for Phase 7.

**Exit gate:** all transformers produce IR and output is printed by our printer; on every spec the original handles:
100% type identity and ≥ 99% byte identity (after header normalization). Every remaining byte difference is listed
in the report with a reason; a difference without a reason is a bug.

## 7. Testing strategy

| Level | What | Tooling | Gate |
|---|---|---|---|
| Unit | IR constructors, printer, each `SchemaRule`, each transformer, naming and escaping | vitest | ≥ 90% lines + branches (domain/application: aim 100%) |
| Property-based | Escaping, identifiers, printer round-trips, union normalization | fast-check | No counterexamples |
| Golden (examples) | Inherited `examples/` outputs, type-checked | vitest + `tsc` | Byte-identical |
| Corpus compatibility | APIs.guru + curated specs, text + type equivalence | custom harness | Subset on PR, full nightly / pre-release |
| Type matrix | Generated types and client on TS 5 / 6 / 7 | `tsc` per version | Green |
| Node API compat | Inherited `node-api.test.ts` + legacy callbacks | vitest | Green |
| CLI e2e | Real CLI process: flags, stdin/stdout, files, exit codes, errors for removed flags | vitest + execa | Green |
| Client e2e | Browser and Node runtimes | playwright, vitest | Green |
| Real projects | Dependents switched by package name | scripted | Green |
| Performance | Generation time and memory on largest specs | benchmark script | No regression > 10% |

Test conventions: `describe("<unit>")` + `it("<function> <scenario> <expected>")`; Arrange–Act–Assert; in-memory fakes for ports; no network in unit tests; deterministic inputs.

## 8. Definition of Done (every pull request)

- [ ] Conventional Commit title; one logical change.
- [ ] Tests added or updated; failing test first for bug fixes.
- [ ] Coverage did not drop; gate passes.
- [ ] Corpus subset: 100% of previously matching specs still match.
- [ ] No new runtime dependency without an ADR.
- [ ] No layer violation (dependency-cruiser), no warnings (biome, tsc).
- [ ] Functions ≤ 30 lines, ≤ 4 parameters; nesting ≤ 3.
- [ ] Public API change → changeset + docs update; breaking change → `!` + `BREAKING CHANGE:` footer.
- [ ] English only in code, comments, docs, commit message.

## 9. Dependency policy

- `openapi-typesafe-fetch`: zero runtime dependencies (target; helpers inlined if possible).
- `openapi-typesafe` (generator): only dependencies that are (a) necessary, (b) actively maintained, (c) small, (d) pinned via lockfile. Each one is justified in ADR-003 or a later ADR.
- Every new or updated dependency: check the current stable version first (CODING_PRINCIPLES §7.10); review changelog for majors.
- Candidates to remove or replace (to be decided with data): `ansi-colors` + `supports-color` (Node has `util.styleText`), `change-case` + `scule` (overlap), `parse-json`, `yargs-parser` (Node has `util.parseArgs`). Each removal must keep CLI behavior identical.

## 11. Risks

| Risk | Mitigation |
|---|---|
| Printer output drifts from the original in edge cases | Construct-level parity tests (4.3) + full corpus with type identity (2.4) |
| Corpus under-represents OpenAPI 3.1 / 3.2 (only 96 × 3.1 in APIs.guru) | Curated 3.1 / 3.2 specs in 2.1; unit tests for 3.1-only keywords (`const`, type arrays, `$defs`, `prefixItems`) |
| Private-repo CI minutes run out | Heavy jobs locally until publication (1.7) |
| Users expect 7.13.0 output, but the fork base already contains unreleased upstream changes | Two golden sets (2.2); the 7.13.0 ↔ fork-base diff is documented in the report and the migration guide |
| No provenance while private | Closed beta via tarballs (11.1); first npm publish only after the repository is public (11.2–11.3) |
| Legacy AST callbacks are more common than expected | Measure first (3.1); optional bridge + codemod (6.4, 10.1) |
| `@redocly/openapi-core` dependency weight or behavior | ADR-005 with corpus data; loader is behind a port, so replacing it is local |
| Strictness flags create a large one-time diff | Per-directory rollout (1.9); new code strict from day one |
| Scope creep | Non-goals (§1); new features only from the ranked backlog after 1.0 |
| Schedule slips (8 weeks is aggressive for one engineer) | Scope-cut list, in this order, if a gate is late by more than one week: (1) Bun / Deno matrix → after 1.0; (2) automatic rewriting of legacy callbacks in the codemod → manual guide only; (3) `openapi-typesafe-react-query` → separate later release; (4) backlog fixes (7.4) → 1.1. Never cut: compatibility harness, type identity gate, release security |
| Single maintainer | Small modules, docs, ADRs, automation; recruit co-maintainers before going public |
