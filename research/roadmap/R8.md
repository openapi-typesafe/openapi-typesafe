# R8. `anyOf` with sibling `properties`

Backlog item 19; upstream issue #2380 and PR #2608 (texts and diff in `.logs/roadmap/R8/`). The
fix is opt-in by ADR-021: `--fix anyof-properties`.

## Problem

```yaml
Contact:
  type: object
  properties: { name: { type: string } }
  anyOf: [{ $ref: Email }, { $ref: Phone }]
```

gives `{ name?: string } | Email | Phone`. JSON Schema applies every keyword of a schema, so a
value must match the sibling keywords and at least one variant; the union accepts `{ name: "Ann" }`.
When a variant is `unknown` (one with only `required`, say), `X | unknown` is `unknown`, and the
whole schema loses its type.

## Change

`anyOfType` in `composition-type.ts`: with the fix, the type of the core keywords (`properties`,
`additionalProperties`, `patternProperties`, a discriminator, or a single `type` such as `string`)
and `allOf` is intersected with the `anyOf` union, as `oneOf` already is. Without a sibling type, `anyOf` stays a plain union. Without
the fix the code path is the same as before.

PR #2608 intersects every sibling type, `type` lists too. That drops `null`: with
`type: [object, "null"]`, `multipleTypes` already applies `anyOf` inside each listed type, so the
core is `null | (…)`, and `(null | …) & (A | B)` has no `null`. Here a `type` list is the whole
type: each listed type has applied `anyOf`, and the outer union is not added again. The result is
`({ name?: string } & (A | B)) | null`.

## Cases covered (tests)

`test/api/anyof-properties-fix.test.ts`: without the fix the union is kept; with it, sibling
`properties` and `allOf` are intersected; a bare `anyOf` stays a union; a `type` list keeps its
`null`; type checks show that a value of one variant compiles, a value of no variant fails with the
fix and compiles without it. Example `examples/anyof-properties.yaml` → `anyof-properties.ts`
(CLI snapshot), used by `tools/type-matrix/consumer/src/anyof-properties.ts` (narrowing by `type`,
`null`, an `@ts-expect-error` for a value of no variant).

Mutation check: intersecting `type` lists fails one test, dropping the "no variant" early return
fails five, inverting the fix check fails six.

## Results

- **Opt-in check, full corpus** (1,820 documents × 3 fix option sets = 5,460 cases): 0
  regressions. `fix=anyof-properties` alone and with `--empty-objects-unknown`: 1,754 unchanged,
  61 changed and compile, 2 changed with no more errors than without the fix, 3 where the baseline
  fails too; `fix=all` (with `allof-required`): 1,457 unchanged, 355 compile, 5 no new errors, 3
  baseline-failed. Over the corpus (63 files) the fix adds 445 intersections with an `anyOf`
  union and removes 123 `| unknown` members that made the whole type `unknown`; 15 of the
  changed types have a primitive core, such as `string & ("lite" | "basic" | …)`, which was
  `string | "lite" | …` (`.logs/roadmap/R8/corpus-fix-diff.txt`, `compat-opt-in-full.log`).
- **Compat, 200-document subset, all 28 option sets:** 5,600 cases, 0 mismatches with `fork-base`
  (`compat-200-all.log`).
- **Found on the way:** the print-parity property test found that R6 merged the parent's
  `required` keys into a set also without the fix, so a key listed twice gave
  `WithRequired<T, "a">` instead of the original `WithRequired<T, "a" | "a">`. Fixed in its own
  commit, with a test; all parity tests then pass with 30,000 cases each (`parity-30k.log`). One
  full-suite run also failed the footer parity test once; it was not reproduced in 60 runs of the
  file, 200,000 cases, or 8 full-suite runs (`footer-loop.log`, `suite-loop.log`), and the footer
  code is not touched here.
- **Type matrix** (TypeScript 5.4 to 7.1 beta, strict and strict flags): pass, with
  `consumer/src/anyof-properties.ts`.
- **Full verify** (`build lint test size coverage types skills`, warnings fail): pass
