# R9. `--array-length` tuples

Backlog item 21; upstream issue #2048 and PRs #2330, #2546 (texts and diffs in
`.logs/roadmap/R9/`). The fix is opt-in by ADR-021: `--fix array-length-tuples`. It needs
`--array-length` (ADR-021 decision 6).

## Problems

| Schema (`--array-length`) | Today | Right |
| --- | --- | --- |
| `minItems: 1, maxItems: 2` | `[] \| [string]` | `[string] \| [string, string]` |
| outer `minItems = maxItems = 1`, inner the same | `[[string][]]` | `[[string]]` |
| outer `minItems = maxItems = 1`, inner `string[]` | `[string[][]]` | `[string[]]` |
| any length tuple with `--immutable` | `[string]` | `readonly [string]` |
| `prefixItems: [a, b]` with `minItems: 2` | `[[a, b], [a, b], ...[a, b][]]` | `[a, b]` |

The cause of the nesting bugs (#2330): `itemType` returns the array type itself for a nested
`type: array` item (it wraps it in an array), and the length tuples then wrap that again.

## Change

`fixedArrayType` in `array-type.ts`, used when `--array-length` and the fix are both on:

- the item type is the nested type as it is; the array or the length tuples are built around it
  once;
- with both bounds, the tuple lengths go from `min` to `max`; with `min` only, `min` items and a
  rest element (as before);
- `--immutable` wraps each tuple in `readonly`, also inside a union;
- a `prefixItems` tuple is the type, without length tuples.

The size limit (`MAX_LENGTH_TUPLE_ELEMENTS`) is unchanged; its estimate already counted the `min`
to `max` tuples. Without the fix, `arrayType` runs the original path. The shared code was split
into `prefixTupleType` and `singleItemType`; the original order of checks stays (a first version
tested `"type" in items` before `!items`, and the print-parity tests caught the `TypeError` for
`items: null`).

A fix named without `--array-length` changes nothing, and `createDocumentRun` warns through the
logger: `Fix "array-length-tuples" has no effect without arrayLength (--array-length)`. The rule is
data (`REQUIREMENTS` in `domain/output-fixes.ts`), so R13 adds `--root-types` the same way. The
logger covers the CLI, `redocly.yaml` APIs and the Node API alike. `all` gives no notice: it means
every fix that applies.

## Cases covered (tests)

`test/api/array-length-tuples-fix.test.ts` (16): the old `0..max-min` tuples without the fix;
`min..max` with it; `minItems` only; a length tuple in a length tuple; a plain array in a length
tuple; nested arrays without bounds unchanged; `readonly` for unions, rest tuples and plain arrays;
`prefixItems` without length tuples; no `items`; a tuple item from a `type` list; no change without
`--array-length`; type checks (one and two items compile, `[]` fails); the notice once per name, none
with `--array-length`, none for `all`. Example `examples/array-length-tuples.yaml` (CLI snapshot)
and `tools/type-matrix/consumer/src/array-length-tuples.ts` (`tags[0]` is a `string`; empty, too
long and over-nested values fail with `@ts-expect-error`).

Mutation check: each of these fails at least one test: lengths from 0, no `readonly` on union
members, rest tuples or plain arrays, length tuples around `prefixItems`, the fix without
`--array-length`, the notice without its option check, the notice without de-duplication. A check
that `all` has no requirement caught nothing (the table has no `all` entry) and was removed.

  regressions. `fix=array-length-tuples` with `--array-length` (baseline `array-length`): 1,744
  unchanged, 72 changed and compile, 1 changed with no more errors than without the fix, 3 where
  the baseline fails too. `fix=all`: 1,457 / 355 / 5 / 3 (as in R8: without `--array-length` this
  fix adds nothing); `fix=all` with `--array-length`: 1,448 / 364 / 5 / 3. Over the corpus (73
  files) 376 declarations change; 268 of them were ranges that started at `[]`, 2 were nested
  arrays wrapped twice (`.logs/roadmap/R9/corpus-fix-summary.txt`, `corpus-fix-diff.txt`).

  (`compat-200-all.log`).

  `consumer/src/array-length-tuples.ts`.
- **Full verify** (`build lint test size coverage types skills`, warnings fail): pass. The first
