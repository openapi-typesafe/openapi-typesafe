# Contributing

Thank you for helping. This guide covers setup, the rules every change must follow, and package-specific notes.

## Before you start

- For a bug fix, open an issue (or comment on an existing one) with a minimal schema that reproduces the problem.
- For a feature or a breaking change, **open an issue first**. New features follow the ranked backlog
  ([research/backlog.md](./research/backlog.md)); a breaking change waits for the next major version.

## Setup

Requirements: Node.js 22.12 or newer (the generator's `engines.node`; CI tests 22, 24 and 26) and
[pnpm](https://pnpm.io/) 10 or newer. The `packageManager` field of the root `package.json` pins
the pnpm version of the repository. Any pnpm from 10 on downloads and runs that version when it
differs from the installed one (the default `pmOnFail: download`, `managePackageManagerVersions`
in pnpm 10), so one global install is enough:

```sh
npm install --global pnpm
```

Node.js 25 and newer no longer ship Corepack, so `corepack enable` works only after
`npm install --global corepack`.

```sh
pnpm install
pnpm build
pnpm test
```

The repository is a pnpm workspace driven by [Turborepo](https://turbo.build/repo/docs). Commands run at the root apply
to every package; `pnpm --filter <package> <script>` runs one package.

Packages depend on each other: `openapi-typesafe-fetch` tests use types generated by `openapi-typesafe`, and
`openapi-typesafe-react-query` uses the fetch client. **Tests run against the built `dist/` output**, so rebuild
(`pnpm build`) after changing source code, or the tests will see stale code.

| Command | What it does |
|---|---|
| `pnpm build` | Build all packages |
| `pnpm test` | Run all test suites (unit, type tests, examples type-check, `attw`) |
| `pnpm lint` | Biome and `tsc` for all packages |
| `pnpm format` | Format with Biome |
| `npx size-limit` | Check the fetch client size budget |
| `pnpm verify` | Run build, lint, test and size with one log file per step in `.logs/verify/`; fails on any error |

## Rules for every change

Every pull request must meet the Definition of Done in [ENGINEERING_PLAN.md](./ENGINEERING_PLAN.md) §8. In short:

1. **Conventional Commits.** Commit messages and PR titles follow
   [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/): `type(scope): description`, in English,
   imperative mood, lowercase, no trailing period. Breaking changes use `!` and a `BREAKING CHANGE:` footer.
2. **One logical change per commit.**
3. **Tests first for bug fixes.** Add a failing test, then the fix. Every behavior change has a test.
4. **No drop in coverage**, no new warnings (Biome, `tsc`, tests, install logs).
5. **No new runtime dependency** without an Architecture Decision Record in `adr/`.
6. **English only** in code, comments, docs and commit messages. Comments explain *why*, not *what*.
7. **Changesets.** A change that affects a published package needs a changeset: run `npx changeset` and describe
   the change from the user's point of view. Name no ADR, audit finding or hunt item in it; the pull
   request and the commit carry those (ADR-040 rule 8, checked by `pnpm lint`).

## Package notes

### `openapi-typesafe` (generator)

- Tests live in `test/`, by layer like `src/` (`domain/`, `application/`, `adapters/`, `api/`, `cli/`,
  `transform/`); `node-api.test.ts` and `cli.test.ts` cover the public surfaces. Prefer a small schema fragment per test over a full-schema snapshot.
- `examples/` holds generated output for real APIs. It is type-checked in CI (`pnpm run test:examples`).
  Regenerate it only when a change is meant to alter the output: `pnpm run update:examples` (downloads remote
  schemas). Review the diff line by line.

### `openapi-typesafe-fetch` (client)

- Runtime code is in `src/index.js`; public types are written by hand in `src/index.d.ts`. A runtime change almost
  always needs a matching type change. (Whether to convert the client to TypeScript is decided in ADR-008.)
- Test the *types* as well as the runtime: use `assertType<T>()` and `// @ts-expect-error` scoped to a single line.
  Avoid `test.each` for type tests; it can hide type errors.
- The bundle has a size budget (`size-limit` in the root `package.json`). Check it with `npx size-limit`.

### `openapi-typesafe-react-query`

- Tests use the fetch client against a mock server (`msw`, `test/fixtures/mock-server.ts`); build the client before
  running them.

## Opening a pull request

- Keep the PR focused; link the issue it resolves (`Closes #123`).
- Describe what changed and why, and how you tested it.
- CI must be green. A yellow CI (warnings) counts as red.

## Troubleshooting

- **Tests do not see my change.** Most tests import the built `dist/` output. Run `pnpm build` first.
- **`pnpm install` rejects a version.** The workspace refuses versions published less than 24 hours ago
  (`minimumReleaseAge`). Pick the previous release or wait a day.
- **Firefox e2e fails locally with "Could not find profile folder".** Seen with Playwright 1.64 on macOS 27.
  Chromium and WebKit are unaffected, and CI runs the browser tests on Linux. Run
  `pnpm --filter openapi-typesafe-fetch exec playwright test --project=chrome --project=webkit` locally.
