# R5. How opt-in output fixes are exposed

The decision is [ADR-021](../../adr/021-opt-in-output-fixes.md). Upstream texts in
`.logs/roadmap/R5/`.

## Summary

Six steps (R6, R8, R9, R11, R12, R13) change the output of valid schemas, so each is opt-in in 1.x.
They share one option: `--fix <names>` / `fix: [...]` / `x-openapi-ts.fix`, with `all` for every
fix of the installed version. Upstream's PRs for the same issues change the default output, so
there is no upstream flag to follow.

## What the first fix step (R6) adds

- `OUTPUT_FIXES` and `OutputFix` in the Node API types, with TSDoc; `fix` in
  `OpenAPITSBaseOptions` and in the run context.
- `--fix` in `cli-arguments.ts` (string, repeatable, comma-separated, like `--remote-ref-hosts`)
  and one line in `help-text.ts`; `fix` in the Redocly API settings.
- The error code `OPTION_FIX_UNKNOWN` in `ERROR_CODES` and the CLI table (ADR-011).
- `docs/cli.md#fix` with the table of fixes; links from `docs/node.md`, the migration guide and
  the skill reference.
- Harness option sets `fix=<name>`, `fix=all`, and the pairs with the flags a fix interacts with.

Each later step adds its name to `OUTPUT_FIXES`, a docs row and its option sets.
