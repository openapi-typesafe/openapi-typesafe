# openapi-typesafe-react-query

openapi-typesafe-react-query is a small, type-safe wrapper (about 4.1 kB minified, 1.8 kB gzipped) around [@tanstack/react-query](https://tanstack.com/query/latest/docs/framework/react/overview) to work with OpenAPI schema.

It works by using [openapi-typesafe-fetch](../openapi-typesafe-fetch) and [openapi-typesafe](../openapi-typesafe) so URLs, parameters, request bodies and responses are checked against your schema, with no manual types,
no `any` and no `as` assertions.

A maintained, drop-in successor to `openapi-react-query` (see the [repository README](../../README.md)).

> **Release candidate.** The current version is a 1.0.0 release candidate (`1.0.0-rc.N`);
> names and output can still change before 1.0.0.

## Setup

Install this library along with [openapi-typesafe-fetch](../openapi-typesafe-fetch) and [openapi-typesafe](../openapi-typesafe):

```bash
npm i openapi-typesafe-react-query openapi-typesafe-fetch @tanstack/react-query
npm i -D openapi-typesafe typescript
```

Next, generate TypeScript types from your OpenAPI schema using openapi-typesafe:

```bash
npx openapi-typesafe ./path/to/api/v1.yaml -o ./src/lib/api/v1.d.ts
```

## Usage

Once your types have been generated from your schema, you can create a [fetch client](../openapi-typesafe-fetch), a react-query client and start querying your API.

```tsx
import createFetchClient from "openapi-typesafe-fetch";
import createClient from "openapi-typesafe-react-query";
import type { paths } from "./my-openapi-3-schema"; // generated by openapi-typesafe

const fetchClient = createFetchClient<paths>({
  baseUrl: "https://myapi.dev/v1/",
});
const $api = createClient(fetchClient);

const MyComponent = () => {
  const { data, error, isPending } = $api.useQuery("get", "/blogposts/{post_id}", {
    params: {
      path: { post_id: "5" },
    },
  });

  if (error) return `An error occurred: ${error.message}`;

  if (isPending || !data) return "Loading...";

  return <div>{data.title}</div>;
};
```

> You can find more information about `createFetchClient` in the [openapi-typesafe-fetch documentation](../openapi-typesafe-fetch).

## Errors

`error` is the error body that the schema declares, a `ResponseError` when the response failed
without a body, such as an empty `503` from a proxy, or the `Error` of a request that got no
response to read (a network or parse error). Tell a `ResponseError`, which carries `status` and
`response`, apart with `isResponseError(error)` (`import createClient, { isResponseError } from
"openapi-typesafe-react-query"`). openapi-react-query did not see such a failure: a
mutation succeeded, and a query failed with TanStack's `Query data cannot be undefined`. See
[Errors](https://github.com/openapi-typesafe/openapi-typesafe/blob/main/docs/react-query/index.md#errors).

## Migrating from openapi-react-query

```diff
- import createClient from "openapi-react-query";
+ import createClient from "openapi-typesafe-react-query";
```
