# IR printer: corpus parity and performance (task 4.5)

Date: 2026-11-02. Script: `packages/openapi-typesafe/scripts/bench-printer/main.ts`. Logs:
`.logs/bench-printer/*.jsonl`.

## Method

For each file generated by the fork base (`tools/compat-harness`, outputs in `.cache/compat/outputs/fork-base`):

1. Parse the file body (the part after the generated header) and convert every declaration to IR
   (`scripts/bench-printer/typescript-to-ir.ts`). Unknown syntax throws; nothing is approximated. The
   injected `WithRequired` helper stays a raw declaration, as the generator inserts it as text.
2. **Identity:** `printNodes(ir)` must equal the file body byte for byte, and so must the original path
   (IR → `ts.factory` nodes via the type-AST bridge → TypeScript printer).
3. **Speed:** median of 5 runs after one warm-up run (Node 26.0.0, TypeScript 5.9.3, Apple Silicon):
   - *ts build+print*: build `ts.factory` nodes from IR and print them, as the original generator does;
   - *ts print*: print prebuilt nodes only, the strictest baseline;
   - *ir print*: `printNodes`.

   The gate is *ir print* ≤ *ts print*. For files where *ts print* takes less than 10 ms, the timing is
   reported but not enforced: timer resolution and GC noise dominate there.

## Findings

- The generator sometimes builds a union with a single member, which the TypeScript printer
  parenthesizes as an array element (`(string)[]`). The IR keeps that union and the printer applies the
  same rule, so the output matches. The converter in step 1 restores such unions from the parentheses.
- Some types are built from text, not from factory nodes: template literal path keys
  (`pathParamsAsTypes`, via `stringToAST`) and root type aliases (`components['schemas']['Name']`, an
  identifier holding the whole text). They map to `raw` IR nodes (`irRaw`), which keeps the spelling.
