# Migrating from openapi-typescript

openapi-typesafe is a drop-in successor. A project on these packages moves by changing names:

| Before | After |
| :-- | :-- |
| `openapi-typescript` 7.x (package and command) | `openapi-typesafe` |
| `openapi-fetch` 0.x | `openapi-typesafe-fetch` |
| `openapi-react-query` | `openapi-typesafe-react-query` |
| `openapi-typescript-helpers` | `openapi-typesafe-helpers` |

All four packages have one version number. The generated types are the same, the CLI flags are the same, and `redocly.yaml` keeps its `x-openapi-ts` settings.

Coming from openapi-typescript **6.x**? Follow the [upstream guide to 7.x](https://openapi-ts.dev/migration-guide) first, then this one.

## 1. Run the migration tool

In the project root, with a clean git tree:

```bash
npx openapi-typesafe-migrate          # report what would change
npx openapi-typesafe-migrate --write  # change the files
```

It renames the packages in every `package.json` and in pnpm catalogs, the module specifiers in your sources, and the `openapi-typescript` command in `package.json` scripts, shell scripts, CI files, Makefiles and Dockerfiles. It also writes the new spelling of [CLI flags that openapi-typescript renamed](#renamed-cli-flags). A legacy [`transform` callback](#legacy-callbacks) that only returns `ts.factory` types becomes type text with `irCallbacks: true`.

Whatever it cannot change safely, it lists with the file and line: version specs such as `latest`, `overrides`, renamed peer dependencies, `npx openapi-typescript@<version>`, deep imports, and callbacks it cannot rewrite. Every finding also goes to a log file whose path it prints. See the [tool’s README](https://github.com/openapi-typesafe/openapi-typesafe/tree/main/packages/openapi-typesafe-migrate) for details.

Prefer to do it by hand? Rename the packages in the table above in `package.json`, imports and scripts; nothing else is required.

## 2. Install and regenerate once

```bash
npm install            # or pnpm install, yarn, bun install
npm run generate       # your script that runs openapi-typesafe
```

Commit the regenerated files once. Unless one of the [output fixes](#output-fixes) applies, the only changes are the comments that name the generator, first the header line:

```diff
 /**
- * This file was auto-generated by openapi-typescript.
+ * This file was auto-generated by openapi-typesafe.
  * Do not make direct changes to the file.
  */
```

A schema with a `discriminator` also gets the generator's name in the comment of each added
discriminator property: `@description discriminator enum property added by openapi-typesafe`.

If you check generated files in CI with `--check`, it fails until this commit lands, because the files on disk still carry the old header.

## 3. Type check and test

Run your type check and tests. For the generator and the client, nothing else changes, with the exceptions below.

## What is different

### Node.js

openapi-typesafe needs Node.js **22.12** or newer (the client and helpers: Node.js 22). The CommonJS build loads ESM-only dependencies with `require()`, which Node.js supports without a flag from 22.12.

### No TypeScript dependency

The generator does not need the `typescript` package. It prints types itself, so it runs next to TypeScript 7 (see [TypeScript 7](/typescript-7)). `typescript` is an optional peer dependency, loaded only by the legacy callbacks below.

### Node API returns IR

`openapiTS()` returns the declarations as IR objects (`IrDeclaration[]`), not TypeScript compiler nodes. `astToString(await openapiTS(…))` works unchanged and prints the same text. Code that inspected or edited the returned `ts.Node`s must use the IR objects instead. The helpers (`tsUnion`, `NULL`, `STRING`, …) and the exported transformers return IR too; they still accept TypeScript nodes as input. See [Node.js API](/node).

### Legacy callbacks

`transform`, `postTransform` and `transformProperty` that work with TypeScript nodes keep working in 1.x, with a deprecation warning, as long as a TypeScript JavaScript API can be loaded: `typescript` 6 or earlier, or `@typescript/typescript6` in a TypeScript 7 project. Move them to [IR callbacks](/node#ir-callbacks) (`irCallbacks: true`), which return IR or plain type text such as `"Date | null"`. The TypeScript-node forms are removed in 2.0.

### Renamed CLI flags

As in openapi-typescript 7, the old spellings fail with an error that names the new one: `--immutable-types` and `-it` (use `--immutable`), `--support-array-length` (`--array-length`), `--redoc` (`--redocly`) and `-ap` (`--additional-properties`).

### CLI exit codes and errors

Failures now exit with a documented code: `1` stale output with `--check` (as before), `2` usage or configuration, `3` input document, `4` output files, `70` unexpected error. Before, every failure exited with `1`. See [exit codes](/cli#exit-codes). `--check` without `--output` (and without `apis` in `redocly.yaml`) now fails with `2` and `CLI_CHECK_OUTPUT_MISSING`; before, it printed the types and passed without checking anything.

OpenAPI 3.2 documents get types for `query` and `additionalOperations` operations, `itemSchema` (an `itemContent` map next to `content`), `in: querystring` parameters and `components.mediaTypes`; openapi-typescript leaves them out. `HttpMethod` from `openapi-typesafe-helpers` includes `"query"`, and the fetch client has `QUERY()`. A `Record<HttpMethod, …>` you write yourself needs a `query` entry. The path-based client no longer offers `PARAMETERS()`, which was typed but always failed. See [OpenAPI 3.2 support](/introduction#openapi-3-2-support).

Errors thrown by the Node API are `OpenAPITypesafeError`s with a stable `code` (see [errors](/node#errors)). The messages are unchanged. A file system error is kept as `cause`: check `error.cause.code` instead of `error.code === "ENOENT"`.

### Output fixes

Where openapi-typescript’s output did not compile, was unsafe or had wrong types, it changes:

- `--enum` and `--enum-values` output that did not compile now does.
- `--root-types` with `--enum`: a root type alias that had the same name as an enum gets a suffix (`ClusterState_2`).
- `--root-types`: a root type alias that had the same name as a helper type of the file (a schema named `WithRequired` with `--root-types-no-schema-prefix`) gets the same suffix (`WithRequired_2`).
- `--root-types` names that were not identifiers now are: `--root-types-keep-casing` writes characters such as `-` as `_` (`SchemaAddress_3`), and `--root-types-no-schema-prefix` keeps the prefix before a digit (`Schema1`) and before a name that TypeScript reserves, which only `--root-types-keep-casing` can give (`Schemavoid`, not `void`).
- Names and URLs from the document are escaped where they reach code (`--root-types`, `--path-params-as-types`), so a document can no longer add code to the generated file.
- The `inject` option is printed as written, so comments in it are kept.
- `--make-paths-enum`: `ApiPaths` members whose names collided (`GetUser` for both `/user` and `/user/{user_id}`) did not compile. Colliding names built from the URL now name the path parameters (`GetUserByUserId`); names that still collide, such as a repeated `operationId`, get a number (`listItems2`). Names that did not collide stay the same.
- `--enum` and `--make-paths-enum`: values whose member names come out the same after invalid characters are replaced (`reactions-+1` and `reactions--1` are both `reactions_1`) did not compile. A repeated name gets a number: `reactions_1_2` (a quoted name gets it inside the quotes). Names that did not collide stay the same.
- `--exclude-deprecated`: a deprecated schema that kept output still references (an array's `items`, a kept operation's response) was left out, so the output named a missing `components["schemas"]` key. It is kept now; a deprecated schema that only dropped parts reference is still left out.
- `--path-params-as-types`: a template key such as `` `/apps/${string}` `` also matches `/apps/regions` and `` `/apps/${string}/restart` ``, and that output did not compile (TS2411, TS2413) when their types do not fit the template's. When a path surely does not fit (a method or a parameter location one has and the other has not), `paths` is now an intersection type alias, `` { … } & { [path: `/apps/${string}`]: … } ``, and every path keeps its type. Output that compiled stays the same, `export interface paths` included.
- JSON Schema `$defs` (OpenAPI 3.1): a schema's `$defs` member is optional (`$defs?: { … }`), and a `$ref` into it reads `NonNullable<components["schemas"]["Foo"]["$defs"]>["bar"]`. The root `export type $defs` has one member per subschema; before, it was `Record<string, never>` and `#/$defs/<name>` refs were `never`.

All other output is byte-identical.

### New options

These are off by default, so the output does not change until you turn one on.

- [`--binary-as-blob`](/cli#binaryasblob) (`binaryAsBlob`): raw binary strings (`format: binary`, or
  a `contentMediaType` that is not text) become `Blob` instead of `string`. It replaces the `Blob`
  `transform` recipe; the names follow openapi-typescript PR #2878.

- [`--fix`](/cli#fix) (`fix`): opt-in fixes of the output of valid schemas, by name or `all`.
  They become the default in 2.0. The first one, `allof-required`, makes the keys of an `allOf`
  member with only `required` required instead of adding `Record<string, never>`.
  `anyof-properties` intersects `anyOf` with its sibling `properties` instead of adding them to the
  union.
  `array-length-tuples` corrects the `--array-length` tuples (`minItems` to `maxItems` items,
  nested arrays, `readonly`).
  `discriminator-values` gives a schema that a discriminator `mapping` names one enum with the
  mapped values, instead of also adding its schema name, which made the property `never`.
  `unevaluated-properties` types the keys that no other keyword declares with the
  `unevaluatedProperties` schema, instead of ignoring it.

### Client fixes

- A string body with a non-JSON `Content-Type` such as `text/plain` is sent as is, not JSON-encoded.
- A path parameter that makes a `.` or `..` segment is rejected before the request is sent.
- openapi-typesafe-react-query fails on every non-OK response, also one without a body.
- Middleware request ids come from a counter instead of `Math.random()`.
- A `Blob`, `File`, `ArrayBuffer`, typed array or `URLSearchParams` body is sent as is; before, it was JSON-encoded to `{}`.
- A nested object in an `application/x-www-form-urlencoded` body throws instead of being sent as `[object Object]`; write a `bodySerializer` for the format your server reads.
- An object body with `Content-Type: multipart/form-data` is sent as `FormData` (one part per field), not as JSON, and a `multipart/form-data` header without a boundary no longer breaks a `FormData` upload.
- A path that already has a query string gets `&` before `params.query`, not a second `?`.
- `Readable` and `Writable` keep function types, so a `Blob` or `Date` in response data keeps its methods (`data.file.arrayBuffer()`).

The full list, with the upstream issues each change closes, is in the [changelog](https://github.com/openapi-typesafe/openapi-typesafe/blob/main/packages/openapi-typesafe/CHANGELOG.md).
