# Fork-base bugs kept during the port

> Bugs found in the fork base while porting the transformers to IR (ENGINEERING_PLAN Phase 5). Phase 5 allows no
> behavior change, so each one is kept on purpose, with a comment at the code that keeps it. Input for Phase 7
> (tasks 7.4 and 7.6): each fix there changes output, so each needs a test, a changelog entry and a compatibility
> report entry.

| # | Where (ported code) | Bug | Effect |
|---|---|---|---|
| 1 | `application/transform/schema/enum-rule.ts` (`isTsEnum`) | The original meant to allow `null` in `--enum` enums but compared `typeof value` with `null`, which is never true | An enum with a `null` value stays a union of literals instead of becoming a TypeScript enum |
| 2 | `application/transform/footer/enum-naming.ts` (`EnumNaming`; the original: `sanitizeMemberName`, `tsEnumMember` in `lib/ts.ts`) | `JS_PROPERTY_INDEX_INVALID_CHARS_RE` has the `g` flag and is used with `.test()`, which keeps `lastIndex` between calls | Whether a trailing invalid character is removed from an enum name depends on the names converted before it; an invalid character can stay in the output. The port keeps this state per run (`isNextCheckSkipped`). Reproduced: `tsEnum` on `a-`, `b-`, `c-` in a row gives `A`, `B-` (invalid TypeScript), `C` |
| 3 | `lib/ts.ts` (`enumCache`) | `--dedupe-enums` uses a module-level cache that is never cleared | Two runs in one process share enums: the second run can reuse names from the first. **Fixed in Phase 5, step 6** (the plan requires it): the generator uses a per-run registry (`RunFooter`); only the public `tsEnum` still uses `enumCache`. Phase 7 still needs the changelog entry |
| 4 | `application/transform/document/parameters.ts` | `--alphabetize` sorts parameters with `localeCompare` and the default locale, while every other map uses the `en-us` numeric collator | Parameter order depends on the machine's locale and is not natural (`a10` before `a2`) |
| 5 | `application/transform/document/components.ts` (`rootTypeName`) | `--root-types` checks name conflicts before `--root-types-no-schema-prefix` removes the prefix | Two schemas can get the same alias, and the second silently replaces the first |
| 6 | `application/transform/document/components.ts` (`rootTypeAlias`) | Root aliases are written as text with single quotes: `components['schemas']['Pet']` | A schema name containing `'` produces invalid TypeScript |
| 7 | `application/transform/document/webhooks.ts` | A `$ref` webhook is read as a path item | The webhook type has every method as `never` instead of referencing the target |
| 8 | `application/transform/document/response.ts` | A `$ref` entry in a response's `content` is read as a media type without a schema | The media type is `unknown` instead of the referenced type (request bodies and headers resolve it) |
| 9 | `application/transform/document/parameters.ts` | A parameter without a `name` gets the key `"undefined"` | Invalid documents produce a bogus key instead of an error |
| 10 | `application/transform/document/paths.ts` (`pathTemplateText`) | `--path-params-as-types` writes the URL into a template literal without escaping a backtick, then parses the text with TypeScript | A URL with a backtick gives a broken key type (the literal ends at the backtick). **Fixed in Phase 6, task 6.6**: the backtick is escaped, so the key is the intended template literal type. The TypeScript parser is no longer used here |
| 11 | `bin/cli.js` (`checkStaleOutput`) | With APIs in the Redocly config, `--check` runs all APIs in parallel and calls `process.exit(0)` as soon as one output is up to date | The command can exit with 0 before the other APIs are checked, so a stale output goes unnoticed (found in Phase 7, task 7.2). **Fixed in task 7.3** (ADR-012): every API is checked |
| 12 | `application/transform/document/root-type-aliases.ts` (`rootTypeAlias`; the original: `transformComponentsObject` with `rootTypes`) | `--root-types` writes the component name into `components['schemas']['<name>']` as raw text, without escaping | **Code injection.** A name with a quote ends the string, and the rest of the name becomes code in the generated file: `A']; export const x = 1; //` declares `x`. A line break in the name breaks the file. **Fixed in Phase 9, task 9.2**: quotes, backslashes and line terminators are escaped; other names print the same |
| 13 | `application/transform/document/paths.ts` (`pathTemplateText`) | The fix of #10 escapes backticks only | **Code injection.** A backslash before a backtick in the URL escapes the escape, so the backtick ends the literal and the rest of the URL becomes code. `${` in the URL opens a placeholder, and a raw carriage return reads back as a line feed. **Fixed in Phase 9, task 9.2**: the text between `{name}` parts is fully escaped |
| 14 | `cli/cli-arguments.ts` (`REMOVED_FLAGS`; the original: `bin/cli.js`) | The error for the removed `-it` alias says to use `--immutable-types` | That flag is removed too, so following the advice gives a second error. **Fixed in Phase 10, task 10.2**: the message names `--immutable` |
| 15 | `application/transform/footer/enum-naming.ts` (`sanitize`; the original: `tsEnum` / `--enum-values` names) | A name that starts with a digit gets the `Value` prefix before its invalid characters are removed; a name whose digit is first only after sanitizing gets no prefix | A component such as `0 a-b` gives the declaration `export const value0 a-b`, and `§9abc` gives `export const 9abc`: the generated file does not parse. **Fixed in Phase 11** (found by the injection property test): the sanitized name is prefixed. Names that were valid stay the same |
| 16 | `application/transform/document/components.ts` (`rootTypeName`; the original: `transformComponentsObject` with `rootTypes`) | `--root-types-keep-casing` writes the schema name as it is, and `--root-types-no-schema-prefix` drops the prefix even when the name then starts with a digit | A schema `my pet` gives `export type Schemamy pet`, and a schema `1` gives `export type 1`: the generated file does not parse. Two schemas with one PascalCase name, such as `PetStore` and `pet_store`, get one alias without the prefix, and the second replaces the first, so one schema has no root type. **Fixed in Phase 11** (found by the injection property test): characters that cannot be in an identifier become `_`, a name that would start with a digit keeps the prefix (`Schema1`), and a taken prefixed name gets `_2`. Names that were valid stay the same. A kept casing without the prefix could also give a name TypeScript reserves (`void`, `class`), which did not compile either; it keeps the prefix too (`Schemavoid`, roadmap R13). The replaced alias is kept as in the original: that output is valid, so a numbered alias for it is an opt-in for later (backlog 30, pre-beta PB-47) |
| 17 | `application/transform/schema/object-type.ts` (`defsMember`; the original: `transformSchemaObject`) | A schema's `$defs` is printed as a required member `$defs: { … }` | `$defs` is a schema keyword, not data, so a value of the type needs a `$defs` key it never has (upstream #2664, open PR #2835). **Fixed before beta 2** (pre-beta test plan, PB-10): the member is optional, and a `$ref` that indexes past it is wrapped as `NonNullable<…["$defs"]>["name"]`, so it still resolves |
| 18 | `application/transform/document/defs-root.ts` (the original: `transformSchemaObject` on the root `$defs`) | The root `$defs` map is transformed as one schema object | The map has no `type` or `properties`, so the root type is `Record<string, never>` and every `#/$defs/<name>` ref is `never`. **Fixed before beta 2** (PB-11): each entry is a member with its own schema type; an entry that is not a schema gives the usual "Expected SchemaObject" error with its path |
| 19 | `adapters/redocly-loader/bundled-ref-repair.ts` (the original: Redocly 1.x `bundle`) | An external `$ref` to a key with `~`, `/` or `%` is bundled into a component named after the raw pointer segment (`a~0b`, `50%`), and the new local `$ref` is not escaped | Read as a JSON Pointer the ref names another key (`a~b`), so the types do not compile, or it is malformed and the generator throws `URIError` (exit 70). A malformed `%` in a local `$ref` threw the same `URIError`. **Fixed before beta 2** (PB-14): such refs are rewritten to the escaped pointer; a malformed one fails with `SCHEMA_REF_INVALID` |
