# R11. `unevaluatedProperties`

Backlog item 22; upstream issue #2839 and PR #2880 (texts and diff in `.logs/roadmap/R11/`). The
fix is opt-in by ADR-021: `--fix unevaluated-properties`. Valid schemas change, so it is not the
default (plan §3).

## Problem

`unevaluatedProperties` (JSON Schema 2020-12, OpenAPI 3.1) types the keys that no other keyword of
the schema or of its applied subschemas (`allOf`, `anyOf`, `oneOf`, ...) evaluates. The generator
ignores it (`before.txt`):

| Schema | Today | With the fix |
| --- | --- | --- |
| `type: object`, `unevaluatedProperties: { type: string }` | `Record<string, never>` | `{ [key: string]: string }` |
| `properties: { id: integer }` and the same | `{ id?: number }` | `{ id?: number } & { [key: string]: string \| number \| undefined }` |
| `allOf: [$ref Base]` and the same | `Base` | `Base & { [key: string]: string \| PropertyValues<Base> }` |
| `true` or `{}` | ignored | `& { [key: string]: unknown }` |
| `false` | ignored | ignored (no closed object type in TypeScript) |

## Design

The generator already writes `additionalProperties` as an index signature object intersected
with the properties: `{ id?: number } & { [key: string]: string }`. An intersection does not check
its parts against each other, but a value is checked against each part, so `{ id: 1 }` fails the
index signature part: `id` is a number. TypeScript has no type for "the other keys"; the usual
way, and PR #2880's, is to make the index type also hold the declared property types.

| Option | Result |
| --- | --- |
| Index type is only the `unevaluatedProperties` type | A valid value with a declared property of another type is not assignable |
| Mapped type that excludes the declared keys | Not expressible for a string index; breaks `keyof` and lookups |
| Index type holds the declared property types too (chosen) | Every valid value is assignable; a key no keyword declares may also hold a declared type (TypeScript limit) |

PR #2880 finds the declared types by walking the printed AST and, for each `$ref`, transforming
the referenced schema again. Transforming twice has side effects here: `--enum` would declare the
enums of the referenced schema twice, and the footer would get its operations again. So this fix
reads the IR of the composed type instead: the members of each object type (an optional property
adds `undefined`, as TypeScript's own index check does), through unions and intersections; a
reference (`$ref`, `Omit`, `WithRequired`) or raw type is read with a helper,
`PropertyValues<T> = T extends unknown ? T[keyof T] : never`. The helper is distributive, so a
`$ref` to a `oneOf` schema gives the values of each variant, not only of the shared keys
(`keyof (A | B)` is the shared keys). The index signature applies to the whole composition, so it
is added after `allOf`, `anyOf` and `oneOf` (`combinedType`), as one flat intersection.

Rules:

- `unevaluatedProperties` next to `additionalProperties` changes nothing: `additionalProperties`
  evaluates every other key of that schema.
- Only an object schema (`type` absent or `object`) gets it. A type list is typed one listed type
  at a time, so the object of `[object, "null"]` gets it and `null` stays outside.
- `patternProperties` types are part of the index type (they are an index signature already).
- `--enum-values` reads an enum inside `unevaluatedProperties` with `[string]`, as inside
  `additionalProperties`.
- `--immutable` makes the index signature `readonly`.

### Helper name and `--root-types`

A schema named `PropertyValues` with `--root-types --root-types-no-schema-prefix` declared
`export type PropertyValues` next to the helper (`helper-name-clash.ts`). The same was true for
`WithRequired`, in the original too: the output did not compile. The root alias renaming that
already gave way to enums (`ClusterState_2`) now also gives way to the footer's named helper types
(`renameAliasesTakenByFooter`). That changes only output that did not compile, so it is a default
fix (plan §3); its own commit and changeset.

## Cases covered (tests)

`test/api/unevaluated-properties-fix.test.ts` (17): unchanged without the fix; an object with no
properties; declared property types with `undefined`; a referenced `allOf` member through the
helper, declared once; inline `oneOf` variants; `true` and `{}`; `false`; next to
`additionalProperties`; a schema that is not an object; a type list with `null`; `--immutable`;
`nullable` outside the intersection; `patternProperties`; `--enum-values`; the helper name with
root types; and a type check (valid values of an `allOf` and a `oneOf` schema assign, a reading is
typed, a value of the wrong type fails).
`test/application/transform/document/root-type-aliases.test.ts` and
`test/api/root-type-enum-collisions.test.ts`: a helper name, unnamed raw code and value
declarations. Example `examples/unevaluated-properties.yaml` (CLI snapshot) and
`tools/type-matrix/consumer/src/unevaluated-properties.ts`.

Mutation check: each of these fails at least one test: the fix check, `false`, the
`additionalProperties` check, the type check, `type` absent, `{}` and `true` as `unknown`, index
signatures in the declared types, `undefined` for optional members, the helper declaration, the
union walk, the declared types, `readonly`, the `[string]` reading. The first run left two alive
(index signatures, the `[string]` reading); the `patternProperties` and `--enum-values` tests were
added for them.

## Results

- **Opt-in check, full corpus** (1,820 documents × the 16 opt-in sets = 29,120 cases): 0
  regressions (`opt-in-check.log`). The three `unevaluated-properties` sets change nothing: the
  only corpus document with the keyword (train-travel, OpenAPI 3.2) uses `unevaluatedProperties:
  false`, which the fix leaves alone. The tests, the example and the type matrix carry the check.
- **Root alias renaming:** `root-types`, `export-type+root-types` and
  `root-types+root-types-no-schema-prefix` regenerated for the full corpus are byte-identical to
  the R10 run (`root-diff.log`): no corpus schema takes a helper name.
- **Compat, 200-document subset, all 28 option sets:** 5,600 cases, 0 mismatches with
  `fork-base-200` (`compat-200-all.log`).
- **Print parity**, 30,000 runs each: pass (`parity-30k.log`). The parity port of the original
  footer gets a `requirePropertyValues` that throws: the original has no opt-in fixes and the parity
  tests run without them.
- **Type matrix** (TypeScript 5.4 to 7.1 beta, strict and strict flags): pass, with
  `consumer/src/unevaluated-properties.ts` (`type-matrix.log`).
- **Full verify** (`build lint test size coverage types skills`, warnings fail): the first run
  failed lint (a test schema without `type`, and a literal key that Biome wants as `.owner` while
  `noPropertyAccessFromIndexSignature` forbids it, now a `key` parameter); pass on rerun
  (`verify.log`, `verify-rerun.log`). Docs links: 526, 0 broken.
