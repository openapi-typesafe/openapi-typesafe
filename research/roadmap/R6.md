# R6. `allOf` member with only `required`

Backlog item 18. Upstream issues, all open:
[#1474](https://github.com/openapi-ts/openapi-typescript/issues/1474) (4 reactions),
[#1520](https://github.com/openapi-ts/openapi-typescript/issues/1520) (8),
[#2165](https://github.com/openapi-ts/openapi-typescript/issues/2165) (1); open PRs
[#2850](https://github.com/openapi-ts/openapi-typescript/pull/2850) and
[#2858](https://github.com/openapi-ts/openapi-typescript/pull/2858), both changing the default.
Texts, the cases and the outputs are in `.logs/roadmap/R6/`.

## Problem

```yaml
Info:
  type: object
  properties: { name: { type: string }, note: { type: string } }
NamedInfo:
  allOf:
    - $ref: "#/components/schemas/Info"
    - type: object
      required: [name]
```

| Member | Today |
| --- | --- |
| `{ type: object, required: [name] }` (#1474) | `Info & Record<string, never>`: no value fits |
| `{ required: [name] }` | `Info & unknown`: `name` stays optional |
| `$ref` to `{ type: object, required: [...] }` (#2165) | `Info & RequiredProps`, where `RequiredProps` is `Record<string, never>` |
| `$ref` to `{ type: object }` (#1520) | `Empty & { foo?: string }`, where `Empty` is `Record<string, never>` |
| `{ description: … }`, `{ deprecated: true }` | `& unknown` |

A `required` next to `allOf` already works: each `$ref` member becomes `WithRequired<T, keys>` for
the keys its target defines, and each inline member gets the keys in its own `required`
(`composition-type.ts`).

## Design

Behind the `allof-required` fix (ADR-021). A member is **presence-only** when it has only
`required`, `type: object` and annotations the generator does not read on a member (`title`,
`description`, `$comment`, `deprecated`, `example`, `examples`, `x-` extensions), inline or as the
target of a `$ref` without sibling keywords. With the fix, presence-only members are left out of
the intersection and their `required` keys join the parent's `required`, so they reach the other
members by the path that exists. Nothing new is printed: the output uses `WithRequired`, as
before.

| Member | With the fix |
| --- | --- |
| `{ type: object, required: [name] }` | `WithRequired<Info, "name">` |
| `{ required: [name, missing] }` | `WithRequired<Info, "name">` (`missing` is not in `Info`) |
| `$ref` to a presence-only schema | `WithRequired<Info, …>`; the component itself is unchanged |
| `{ type: object }`, `{ description }`, `{ deprecated: true }` | left out |
| inline `{ properties: { a } }` + `{ required: [a] }` | `{ a: string }` |

Upstream #2850 checks that every key exists in a kept member and otherwise keeps the old output;
#2858 resolves keys through `$ref`s. Here a key that no kept member defines is dropped, the same
as a parent `required` key today: the rule is one rule, and the old output for such a key was not
better (`& Record<string, never>`).

### Why these keywords

`default`, `readOnly`, `writeOnly` and `nullable` change types in this generator (default
non-nullable, read/write markers, `| null`), so a member with them is kept. `--exclude-deprecated`
does not read `deprecated` on an `allOf` member (checked: the output is the same with and without
the flag), so it is an annotation here.

### Discriminators

A `$ref` member that a discriminator maps to is never presence-only: the discriminator scan adds
the discriminator property to the target before the transform runs. A test documents it. The
discriminator property of a kept `$ref` member is still omitted (`Omit<WithRequired<…>, "type">`),
as for a parent `required`.

## Combinations

- `--immutable`, `--alphabetize`, `--read-write-markers`: unchanged paths (`WithRequired`, inline
  objects).
- `--properties-required-by-default`: inline members always get a `required` list from the parent
  path, so the flag already does not apply to them; nothing changes.
- `--empty-objects-unknown`: a presence-only member would be `unknown`; it is left out instead.
- `--exclude-deprecated`: see above.
- `fix: ["all"]` gives the same output.

## Left out

- An `allOf` whose members are all presence-only: no member is left to carry the keys, so the
  output stays as it is (`Record<string, never>` with `type: object`, else `unknown`).
- `properties` next to `allOf` with a presence-only member: the parent's own properties are not
  made required by it.
- A `$ref` member with sibling keywords.
- A required key that only a nested composition (`$ref` to an `allOf`) defines.

## Cases covered (tests)

`test/api/allof-required-fix.test.ts`: typed and bare `required` members, unknown keys, inline
siblings, a `$ref` to a presence-only schema, an empty member, annotation-only and deprecated
members, the parent's `required` merged once, members kept for `nullable`, `type: [object, null]`,
`minProperties` and a `$ref` with a sibling, all members presence-only, a mapped discriminator
target, `all`, `--immutable`, strict compilation, an unknown name. `test/cli/fix-option.test.ts`:
`--fix` parsing, repeats, the `redocly.yaml` setting, unknown names (exit code 2).
`test/domain/output-fixes.test.ts`: names and `all`. Mutation check: removing the `type: object`
check, the "`$ref` has no siblings" check or the "a member is left" check fails a test.

## Results (2026-11-03)

- **Opt-in check, full corpus** (1,820 documents × 5 fix option sets = 9,100 cases): 0
  regressions. Each set (`fix=allof-required` alone and with `--immutable`,
  `--properties-required-by-default`, `--empty-objects-unknown`; `fix=all`): 1,519 unchanged, 294
  changed and compile, 4 changed with no more errors than without the fix, 3 where the baseline
  fails too. Over the corpus the fix removes 184 lines with `& Record<string, never>`, removes the
  `& unknown` of annotation-only members, and adds 74 `WithRequired` types
  (`.logs/roadmap/R6/corpus-fix-diff.txt`).
- **Compat, 200-document subset, all 28 option sets:** 5,600 cases, 0 mismatches with `fork-base`.
- **Example:** `examples/digital-ocean-api-fix-all.ts` (`--fix all`), 40 changed lines, among them
  `domain_record_a: WithRequired<domain_record, "type" | "name" | "data">` and
  `floating_ip_action_unassign` without `& Record<string, never>`.
- **Type matrix** (TypeScript 5.4, 5.9, 6.0, 7.0, 7.1 beta; strict and strict flags): pass, with
  `consumer/src/allof-required.ts` (an `@ts-expect-error` proves a key is now required).
- **Full verify** (`build lint test size coverage types skills`, warnings fail): pass; the new
  files have 100% line and branch coverage. Docs build and links: 521 links, 0 broken.
