# R4. Workspace on TypeScript 6

Logs in `.logs/roadmap/R4/`.

## What pinned the compiler to 5.9

- **ADR-006 decision 4:** "TypeScript 5.9 until Phase 6", because the generator printed through
  the compiler API. Phase 6 is done: `src/` loads `typescript` only in the legacy bridge
  (ADR-004), which accepts TypeScript ≤ 6 or `@typescript/typescript6`.
- **`research/toolchain.md`:** the same rule, plus SvelteKit 3 waiting for it (it needs
  TypeScript 6 as a peer).
- **Compiler API users that run on the workspace compiler:** the generator tests of the legacy
  bridge and the print parity tests, the compat harness type checks, the skill evals. All of them
  work on TypeScript 6 unchanged. `openapi-typesafe-migrate` uses `@typescript/typescript6`, and
  the type matrix installs each tested version under its own alias, so neither depends on the
  catalog.
- **`unbuild` 3.6.1** (latest, declarations through `rollup-plugin-dts`) declares the peer
  `typescript: ^5.9.2`. It builds with TypeScript 6 without a warning. Upstream has the fix open
  ([unjs/unbuild#573](https://github.com/unjs/unbuild/pull/573), issue
  [#566](https://github.com/unjs/unbuild/issues/566)); until it is released,
  `pnpm-workspace.yaml` allows `unbuild>typescript: "6"`. Replacing `unbuild` is backlog item 31.

## Why 6 and not 7

TypeScript 7.0.2 is the latest release, but it has no JavaScript compiler API. `unbuild`
declarations and the legacy bridge need one. 7.0 and 7.1 stay test targets of the consumer
matrix; the move to 7 is the review trigger of ADR-006 (a build tool without the compiler API).

## Changes

| `pnpm-workspace.yaml` | catalog `typescript: ^6.0.3`; the `unbuild` peer rule | above |

| nextjs and vue-3 examples | drop `baseUrl` | deprecated in TS 6 (TS5101); the `paths` are already relative |
| SvelteKit example | kit 3.1.1, adapter-auto 8.0.0, svelte-check 4.7.8 | below |
| `.github/dependabot.yml` | drop the two SvelteKit major ignores | they waited for this step |

### SvelteKit 3

- `svelte.config.js` is gone: the options go to `sveltekit({ adapter, preprocess })` in
  `vite.config.ts`.
- `$lib` is gone: `package.json` `imports` maps `#lib` and `#lib/*` to `src/lib`, and the routes
  import `#lib/api/index.js`. (The other choice, an `alias` for `$lib`, keeps an old name alive.)
- `Handle` is imported from `@sveltejs/kit/hooks`.
- `tsconfig.json` extends `$app/tsconfig`.

## Left as is

The skill-eval task fixtures (`tools/skill-evals/tasks/*`) pin `typescript: ^5.9.3`. They are
user projects that the agent migrates, and 5.9 is a supported consumer version (ADR-006), so they
stay.

## Results (2026-11-03)

- Install: no peer warnings.
- Full verify (`build lint test size coverage types skills`): pass, zero warnings.
- `dist` of every package is byte-identical to the TypeScript 5.9 build and to the `beta.4`
  tarballs.
- Type matrix: 5.4, 5.9, 6.0, 7.0, 7.1 beta pass.
- Examples: SvelteKit `check` (0 errors, 0 warnings) and `vite build`; vue-3 `type-check` and
  `vite build`; nextjs `tsc --noEmit`. Logs `sveltekit-*.log`, `vue-*.log`, `nextjs-tsc.log`.
