# R10. Invalid-output fixes

Backlog items 27, 28, 29: three option combinations where the output does not compile, in
openapi-typescript 7.13 and here. Plan §3 lets a fix of output that does not compile be the default
(it cannot break code that compiles); each one leaves output that compiles byte-identical. Logs and
reproductions are in `.logs/roadmap/R10/`.

## R10.1 `--enum` member collisions (backlog 27)

Member names are built from values; characters that are not valid in a name become `_`, so
`reactions-+1` and `reactions--1` are both `reactions_1`, a "Duplicate identifier" (GitHub
example: 26 errors).

`enumDeclaration` now numbers a repeated member name after the names are built: `reactions_1`,
`reactions_1_2`. A number whose name another member already has is skipped; a quoted name gets the
number inside the quotes (`"+_2"`). The numbering is the one PB-38 wrote for `ApiPaths`, moved to
`numbered-names.ts`; `ApiPaths` keeps its own format (`listItems2`) and now also numbers names that
collide only after sanitizing (`get-user` and `get_user`). The separator `_` keeps
`reactions_1_2` from reading as `reactions_12`.

Tests: `test/api/enum-member-collisions.test.ts` (shared names, a taken number, quoted names,
`ApiPaths`, the output compiles).

The print-parity tests compare with the original only where its output is valid. The duplicate
check covered `ApiPaths` only; it now covers every enum and counts members across declarations of
one name, which TypeScript merges. That also explains the footer-parity failure seen once in R8: the
original declared the same enum twice, so its member was declared twice, and the new footer
declares it once. With the check, the footer test passes 200,000 cases and every parity test
30,000.

## R10.3 `--exclude-deprecated` references (backlog 29)

A deprecated component was always left out, also when a kept schema pointed to it (DigitalOcean:
`droplet.kernels` has `items: { $ref: kernel }`), so the output named a missing key (TS2339).

`keptDeprecatedComponents` (`kept-deprecated.ts`) scans the document before the transform and
returns the deprecated components that kept output references; `componentsType` keeps them. The
scan follows the generator's rules: a property, parameter, operation or path item whose own object
(or `$ref` target, where the generator resolves it) is deprecated is dropped, so its references do
not count; keys the generator does not type (`example`, `examples`, `links`, `callbacks`, `x-…`
and others) are not followed. A kept deprecated component is scanned in turn, so a chain is kept.
Components are matched by object, not by `$ref` text, so a name escaped in the `$ref` (`Old~1v1`)
matches. On DigitalOcean the only change is the `kernel` schema (26 lines), and the output
compiles.

Tests: `test/api/exclude-deprecated-references.test.ts` (11: items, unreferenced, a dropped
property, a deprecated referrer, a chain, a kept and a deprecated operation, a deprecated parameter
and path item, examples and extensions, an escaped name). Each scan rule fails at least one test
when removed.

## R10.2 `--path-params-as-types` overlaps (backlog 28)

### Problem

A path with parameters becomes an index signature over a template literal type. `${string}`
matches `/`, so `` `/v2/apps/${string}` `` also matches `/v2/apps/regions` and
`` `/v2/apps/${string}/restart` ``. In one object type, TypeScript requires every property and
narrower signature that a signature matches to be assignable to its type: TS2411 and TS2413
(DigitalOcean: 128 errors, GitHub: 820; `*-path-params-before.err`).

### Design

| Option | Result |
| --- | --- |
| A union of the covered types as the signature's type | Compiles, but `` paths[`/v2/apps/${string}`] `` becomes a union: the main use (a template lookup) loses its type |
| Narrow `${string}` to one segment | TypeScript has no "string without `/`" type |
| One object type per covering signature, in an intersection (chosen) | Compiles: an intersection does not check its parts against each other |

The choice was checked before writing it (`.logs/roadmap/R10/`, probe): for a property, a covering
signature, a covered signature and a concrete URL, an intersection gives the same type as the one
object (`C`, `A`, `A & B`, `A & B`). A literal property is not intersected with a signature of
another part.

### Change

`pathsType` keeps each member's key (`PathKey`: a URL, or template parts). `coveringTemplateKeys`
(`path-key-overlaps.ts`) finds the template keys that cover another key: it matches one sample of
the other key against the template, by TypeScript's rules for `${string}` (any text, `/` included),
`${number}` (text that converts to a finite number) and `${boolean}`. A covered template's samples
are all covered, so a sample that does not match proves there is no overlap; a sample that
matches may over-report.

A cover is not an error by itself: TypeScript only rejects a covered type that is not assignable
to the signature's type. The first version moved every covering signature, and the full compat run
found 16 documents where the original compiled (`/subscriptions/${string}/${string}` adds a
`subscriber` path parameter, which is assignable) and the output changed. So a signature is now
moved only when `isCoveredPathItemRejected` (`path-item-conflicts.ts`) proves the error. It
compares the two object types property by property, as the checker does: a property the signature
needs and the covered type may lack, or a value where the signature has the `?: never` of an empty
slot (a method the path does not have, an empty parameter location), proves it; two object
properties are compared the same way inside. A required `never` (assignable to everything) and any
pair of types that are not both objects (`operations["…"]` references, unions, keywords) decide
nothing. The check never moves a signature whose output compiles, so that output stays the same;
it may leave a rare error that only a full type check would prove. With a signature to move,
`paths` is `{ rest } & { covering 1 } & …`, and the root becomes an `export type` (an interface
cannot be an intersection).

Checked on the examples: DigitalOcean goes from 128 errors to 4, GitHub from 1,033 to 6
(`do-gh-errors-final.log`; the paths left differ only in referenced operations, response schemas
and union types, which the check does not decide). For
each of the 267 and 673 keys `Old[K]` and `New[K]` are identical with a strict `Equal`, and
`keyof paths` too (`do-eq.ts`, `gh-eq.ts`, from the first version: moving fewer signatures changes
no key's type). `examples/path-params-overlaps.yaml` (CLI snapshot) is used by
`tools/type-matrix/consumer/src/path-params-overlaps.ts`, with the fetch client.

Tests: `test/application/path-key-overlaps.test.ts` (9),
`test/application/path-item-conflicts.test.ts` (12) and `test/api/path-params-overlaps.test.ts`
(10: a covered path with an extra path parameter keeps `interface paths` and compiles; another
method, a missing method, a `$ref` path item). Mutation
check: the number and boolean samples and rules, the self comparison, the end-of-text check, the
split, and each presence rule, the required-`never` guard, the nested comparison and the name
reading each fail a test. A `hasValue` guard that survived was redundant (a `never` is not an
object) and was removed.

## Harness: files TypeScript stops on

The compare against the full golden run (`fork-base-exit`, 50,960 cases) stopped with
`RangeError: Map maximum size exceeded`: TypeScript 6 cannot check Microsoft Graph with
`--path-params-as-types` (24 MB), neither the golden output nor ours (its relation cache passes the
largest `Map`); TypeScript 7.0 did not finish it in 10 minutes. The default output of the same
document compiles. A user's `tsc` stops on that file the same way, so it is a result, not a harness
failure.

`runChecker` (`adapters/checker-limit.ts`) turns a `RangeError` from the TypeScript checker into
the typed error CHECKER_LIMIT, in the output compiler and the identity checker. The compare treats a
file TypeScript stops on as worse than any error count (`error-counts.ts`) and logs
`checker_limit`: ours may stop only where the golden output stops too (golden-invalid), and an
identity check that cannot finish falls back to the compile check, so it is never a pass by
itself. Tests: `checker-limit.test.ts` and three compare cases (both stop, only ours stops, other
errors pass on). The opt-in check stores error counts in JSON, which cannot hold this value, and no
opt-in set reaches such a file, so it still stops on it.

The earlier compare runs (R8, R9) used `fork-base` (9,100 cases) or the 200-document subset; the
full-golden label is `fork-base-exit`, and R10 uses it.

## Results

- **Compat, full corpus against the full golden run** (`fork-base-exit`, 1,820 documents × 28
  option sets = 50,960 cases): 0 mismatches (`compat-final.log`). 49,794 same bytes, 4 same types
  (as before), 168 golden failures (as before), 994 golden output that does not compile (125
  before): ours has no more errors in each, and 766 compile without any
  (`golden-invalid-candidate-errors.log`). By option set: `--path-params-as-types` 791 (600
  compile), `--make-paths-enum` 81 (78), the four `--enum` sets 108 (77), `--exclude-deprecated` 13
  (11), `--root-types-keep-casing` 1 (0). The 869 new cases were byte-identical before, so they
  were never compiled; now that they differ, the compile check runs. 2 of them (Microsoft Graph
  with `--path-params-as-types`) are files TypeScript stops on, golden and ours alike (4
  `checker_limit` log lines). Byte identity over the 49,798 cases that compile: 99.99%; type
  identity 100%.
- **Print parity**, 30,000 runs each: pass (`parity-30k-final.log`); the footer test alone passed
  200,000.
- **Full verify** (`build lint test size coverage types skills`, warnings fail): the first run
  failed lint (an index access in `paths.ts` that `noUncheckedIndexedAccess` rejects); fixed with a
  guard, see `verify-final-rerun.log`. Harness tests: 226 pass.

The compat run used the build before the last two edits (the `paths.ts` guard and the removal of
the redundant `hasValue` check); neither changes output (the guard never fires, and a `never` slot
already decided nothing), and the package tests and CLI snapshots pass after them.
