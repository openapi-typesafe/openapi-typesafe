# R13. Numbered root-type aliases for name clashes

Backlog item 30, pre-beta PB-47 (no upstream issue). The fix is opt-in by ADR-021:
`--fix root-type-numbering`, the name ADR-021 gives it. The output it changes is valid, so it is
not the default (plan §3).

## Problem

`--root-types --root-types-no-schema-prefix` names each root alias after its schema, in
PascalCase. Schemas such as `Void`, `void` and `void-` all get `Void`. The name check in
`rootTypeName` looks at the prefixed name (`SchemaVoid`), but the aliases are kept by the
exported name (`Void`), so a later schema replaces the earlier one: only the last has an alias
(`before` in `after.txt`). That is openapi-typescript's output, and it is valid, so PB-47 kept it.
31 corpus documents have such a clash (PB-47 counted 29: the ones that compiled on both sides).

## Design

| Option | Result |
| --- | --- |
| The first schema keeps the name, the later ones are numbered (PB-47's first fix) | `Void` changes its schema: code that uses it changes meaning without an error |
| The later schema keeps the name, the earlier ones are numbered (chosen, as backlog 30 says) | `Void` stays as it is; the fix only adds exports |

Rules, all only with the fix:

- An alias that a later schema replaces is kept aside. After all component kinds, each one gets
  the next free `Name_2`, `Name_3`, … in document order, and is exported after the other root
  aliases (their order does not change).
- A number that another alias has is skipped (`a_b_2` taken gives `a_b_3`).
- With the prefix there is no clash (`SchemaPet`, `SchemaPet_2` already), so the fix changes
  nothing. It needs both `--root-types` and `--root-types-no-schema-prefix`. A fix requirement is
  now a list of options, and the notice names the ones that are off:
  `Fix "root-type-numbering" has no effect without rootTypesNoSchemaPrefix
  (--root-types-no-schema-prefix)`. The `array-length-tuples` notice text stays the same.
- The footer renaming (`renameAliasesTakenByFooter`, R11) runs after, on every alias.

### Reserved names (default fix)

`--root-types-keep-casing` with `--root-types-no-schema-prefix` writes the schema name as it is.
A schema named `void`, `string` or `import` then gave `export type void = …`, which does not
compile (TS2457 and syntax errors). 57 schemas in 37 corpus documents have such a name
(`reserved-scan.log`). The fix: such a name keeps the prefix (`Schemavoid`), as a name that starts
with a digit already does (legacy bug 16). The 54 reserved names were taken from the TypeScript
6.0 compiler (`export type <name> = 1;` in a module). It changes only output that did not compile,
so it is a default fix (plan §3), in its own commit with a patch changeset. After it, the 37
documents generate and none exports a reserved name (`reserved-after.log`). The compat matrix does
not have keep-casing with no-prefix, so the compat runs do not see it.

## Cases covered (tests)

`test/application/transform/document/components.test.ts`: a reserved name keeps the prefix (and
`voids` does not); with the fix the earlier schema gets `Void_2`; a taken number is skipped; with
the prefix the fix changes nothing; without the fix the later schema has the name (kept).
`test/api/root-type-name-clashes.test.ts`: three schemas give `Void`, `Void_2`, `Void_3`, and a
type check (each alias has its schema's type; `Void` is still the later one).
`test/domain/output-fixes.test.ts`: the notice with both options off, with one off, and none with
the options on, for `all`, or for a fix without needs. Example
`examples/root-type-numbering.yaml` (CLI snapshot) and
`tools/type-matrix/consumer/src/root-type-numbering.ts`.

Mutation check (`mutation.log`, 8 mutants, all killed): the fix check, keeping the replaced alias,
the numbered aliases last, the reserved-name check, the taken names of kept aliases, a number
taken by an earlier numbered alias, the no-prefix requirement, and naming only the missing
options.

## Results

- **Opt-in check, full corpus** (1,820 documents; `fix=root-type-numbering` with both root type
  flags, and `fix=all`, `fix=all+array-length`, each against its baseline: 5,460 cases): 0
  regressions (`opt-in-check.log`). 31 documents change, and only by added lines: 75
  `export type Name_N = components['schemas'][…]` aliases, no line removed or changed. 30 of them
  compile with the fix, one has the same errors as without it.
- **Compat, 200-document subset, all 28 option sets:** 5,600 cases, 0 mismatches with
  `fork-base-200` (`compat-200-all.log`): without the fix the output is unchanged, and the
  reserved-name fix does not touch a matrix set.
- **Reserved names:** 37 corpus documents, 0 reserved aliases after the fix (`reserved-after.log`).
- **Print parity**, 30,000 runs each: pass (`parity-30k.log`).
- **Type matrix** (TypeScript 5.4 to 7.1 beta, strict and strict flags): pass, with
  `consumer/src/root-type-numbering.ts` (`type-matrix.log`).
- **Full verify** (`build lint test size coverage types skills`, warnings fail): the first run
  failed the line length check (a comment that the rename made 102 characters); pass on rerun
  (`verify.log`, `verify-rerun.log`). Docs links: 526, 0 broken (`links.log`).
