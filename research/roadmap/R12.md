# R12. Discriminator value conflict

Backlog item 26, found in pre-beta test plan 10.6 (no upstream issue). The fix is opt-in by
ADR-021: `--fix discriminator-values`. The output it changes is valid, so it is not the default
(plan §3).

## Problem

The discriminator pre-pass (`findDiscriminators`) gives each schema that a discriminator names a
required enum property, so that TypeScript can narrow the union. Pass 1 handles a discriminator
next to a `oneOf`: a `$ref` item gets its `mapping` value, or else its schema name. Pass 2
handles `allOf` inheritance: a schema whose `allOf` holds a `$ref` to a discriminator owner gets
the value that the owner's `mapping` gives it. Each patch adds one more property. A schema that a
parent `mapping` names (`cat` for `Cat`) and that a discriminated `oneOf` without a mapping lists
gets both (`before.txt`):

```ts
Cat: Omit<components["schemas"]["Pet"], "kind"> & { meows?: boolean }
  & { kind: "Cat" } & { kind: "cat" };
```

`kind` is then `never`: no value of `Cat` can be written, though the file compiles. With `--enum`
there are two `CatKind` declarations (`Cat` and `cat`); TypeScript merges them, so that compiles
too (checked with `tsc --strict`). PB-34 already declares an identical enum once. With the fix
there is one `CatKind` with `cat`.

## Design

| Option | Result |
| --- | --- |
| Skip a schema that pass 1 handled in pass 2 (as for `oneOf` in pass 1) | The parent's mapped value is lost; the schema name, which the API may not send, wins |
| Last patch wins | Depends on document order |
| One enum per schema and property; a mapped value wins over a schema name (chosen) | Matches OpenAPI: an explicit `mapping` replaces the implicit schema-name value |

Rules, all only with the fix:

- The scan keeps the enum it added for each schema and discriminator property. A second
  discriminator of that property adds its values to that enum (no duplicates), instead of adding
  a property.
- A schema-name value waits until both passes are done. It is added only for a schema and
  property that no mapping gave a value; two `oneOf`s without a mapping give the name once.
- Two discriminators with different property names still add two properties.
- `scanDiscriminators` (deprecated export) keeps the original behavior.

The in-place patch (`allOf` item or object property) moved to `src/api/discriminator-enum.ts`,
so the scan stays under the file size limit.

## Cases covered (tests)

`test/api/discriminator-values-fix.test.ts` (11): both values without the fix; the mapped value
with it; the schema name where no mapping names the schema; one value from two `oneOf`s without a
mapping; two mappings merged (`"feline" | "cat"`); two agreeing mappings; an object schema's own
property merged; two property names kept apart; output unchanged where every value comes from the
schema name; `--enum` declares one enum with the mapped value; a type check (a value assigns, the
union narrows by `"cat"`, the schema name fails). `test/api/deprecated-utils.test.ts`: the
deprecated scan keeps both values. Example `examples/discriminator-values.yaml` (CLI snapshot) and
`tools/type-matrix/consumer/src/discriminator-values.ts`.

Mutation check (`mutation.log`, 12 mutants): the fix check, the merge, keeping the added enum, not
skipping handled schemas, waiting with schema-name values, the mapped-value check, the value
dedupe, the property in the key, applying the waiting values, marking them handled, the
deprecated scan's setting, and the option wiring. Two survived the first run (marking handled, the
deprecated setting); the unchanged-output test and the deprecated-scan test were added for them.

## Results

- **Opt-in check, full corpus** (1,820 documents; the two `discriminator-values` sets and `fix=all`,
  `fix=all+array-length`, each against its baseline: 7,280 cases): 0 regressions
  (`opt-in-check.log`). Two documents change with the fix, and only by removed lines:
  apple.com sirikit-cloud-media (84 lines) and rebilly.com 2.1 (204 lines, for example seven
  repeated `name: "Other"` properties) lose discriminator properties that repeat one they keep,
  so their types stay the same. No line is added, so no corpus document gives one schema two
  different values: the conflict itself is carried by the tests, the example and the type matrix.
  rebilly.com compiles with the fix; with `--enum` both runs have the same 4 errors.
- **Compat, 200-document subset, all 28 option sets:** 5,600 cases, 0 mismatches with
  `fork-base-200` (`compat-200-all.log`): without the fix the output is unchanged.
- **Print parity**, 30,000 runs each: pass (`parity-30k.log`).
- **Type matrix** (TypeScript 5.4 to 7.1 beta, strict and strict flags): pass, with
  `consumer/src/discriminator-values.ts` (`type-matrix.log`).
- **Full verify** (`build lint test size coverage types skills`, warnings fail): the first run
  failed lint, `discriminator-scan.ts` had 307 lines (limit 300); the in-place patch moved to
  `discriminator-enum.ts`, pass on rerun (`verify.log`, `verify-rerun.log`). Docs links: 526, 0
  broken (`links.log`).
